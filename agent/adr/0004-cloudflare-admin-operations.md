# ADR 0004: Cloudflare Admin Operations Runtime

## Status

Accepted

## Context

The Corpus needs admin-only analytics, a friendlier contribution intake surface,
and an automatic monthly contributor poster. The existing site is Astro static
output served by Cloudflare, while content quality is protected by GitHub pull
requests.

## Decision

Add a Cloudflare Worker beside the existing static assets. Static public pages
remain generated by Astro. Requests to `/admin*` and `/api/*` run through the
Worker first.

The Worker owns:

- Password session creation and verification.
- First-party pageview ingestion through Cloudflare Analytics Engine.
- Signal Deck analytics queries through the Analytics Engine SQL API.
- Admin Submission conversion into GitHub branches, files, and pull requests.
- Contributor Poster generation through Cloudflare Browser Run screenshots.
- Monthly email delivery through Cloudflare Email Service.

Secrets are configured as Cloudflare Worker secrets and are not stored in repo
files.

## Consequences

- The public Corpus stays fast and mostly static.
- Admin tools fail closed when secrets or bindings are missing.
- The contribution path becomes easier without bypassing review.
- Deployment now depends on Cloudflare Worker bindings for Analytics Engine,
  Browser Run, Email Service, and GitHub API credentials.
